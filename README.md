# 分拣过机台（Sortbay）

骨架：过机扫描装载 → 口门路由裁决 → 错分回流批次 → 封袋班次对账

- 前端 http://127.0.0.1:6600
- API http://127.0.0.1:11600

## 封班与过机装载争用：架构A（封班优先，全局唯一口径）

封班入口与装载入口在同一道 `BEGIN IMMEDIATE` 序列化闸上互斥（`app/db.py` 的
`db(immediate=True)`），闸字段 `shifts.sealed` 的检查与落账在同一事务内：

- 封班一旦提交成功，并发装载整笔失败（409）：不留扫描行、不进待路由、
  不落「过机装载」成功审计；主事务回滚到争用前快照。
- 装载先落账，则封班被未清件检查拒绝（409），班次保持未封。
- 败方的「装载被拒 / 封班被拒」在回滚后独立补记审计，争用结局可从审计重放：
  成功事件必有落账，被拒事件必无落账。
- 锁等待超过 `busy_timeout`（10s）时回执为 503「写口争用未决」，同样整笔回滚，
  不会出现假装成功的回执。

不采用「在途装载落完再封」（架构B）：全库无在途登记表、无超时收口状态，
两种口径不得混用。封班后的写口边界（路由/回流/封袋与封班的关系）另立需求。

回归夹具：`backend/tests/test_seal_scan_contention.py`（对撞闭包、半截回滚、
已封仍增待路由、装载成功无行、总览与封班灯长期一致、审计重放）。

```bash
pip install -r backend/requirements-dev.txt
cd backend && python -m pytest tests -q
```
